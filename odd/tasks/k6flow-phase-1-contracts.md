- Local commits authorized; no push, PR, merge or publishing. Native receipts are review evidence, not delivery authorization.

- Zod 4.6.5 explicitly approved; TypeScript 5.9.3 and Vitest 4.0.18 retained. Registry evidence and product decisions live in `docs/DECISIONES.md`.
- Linear execution per VU, no cycles/forks/merges. Connections determine precedence; explicit producer/output references consume earlier results. Draft retention and structural execution-topology validation are separate; full readiness remains 03f.
- HTTP URL/header/query values are whole literals or references, never interpolation/segments. Bodies: none, text, structured JSON. Forms/multipart deferred; reference-shaped literal JSON stays data.
- Scenario authentication: configured HTTP request, uniquely named required JSON-path/header/cookie outputs, explicit string/JSON types. Missing required output/type mismatch declares stop-current-VU-iteration. No Basic Auth/OAuth2, cookie-jar or runtime assumptions approved.
- Checks: explicit response reference; unique independent names; numeric status/duration-ms comparisons; text/header existence, literal equality/inequality and contains; structured JSON-path existence/deep literal equality. Fixed record-failure-and-continue, including missing field/type mismatch. No regex, callbacks or executable expressions.
- CSV pool: external attachment identity only; CSV-order distinct stable row per VU, reused across that VU's iterations; reject insufficient capacity before execution. Required named headers map to unique string outputs without conversion or trimming. These are declarations, not ingestion or allocation implementation.
- Global load: one constant-VU or staged-VU profile; positive safe-integer durations in ms, positive constant VUs, explicit nonnegative stage startup/targets and some positive load. Explicit thresholds may be empty; HTTP latency avg/p90/p95/p99 in ms (finite >=0) or HTTP failure rate as a fraction [0,1], with eq/ne/lt/lte/gt/gte; fixed final pass/fail, no early abort. No defaults/coercion, node overrides, iterations, arrival-rate or arbitrary DSL.
- Composition: kind-tagged typed nodes reuse the reviewed HTTP/auth/check/CSV parameter schemas additively. Each HTTP-request node exposes one built-in reserved `response` output of type `http-response`; checks consume only `http-response`; declared auth/CSV outputs may not be named `response`; auth nodes expose only their declared extraction outputs. Declared `node.references` must exactly equal the set of references embedded in parameter values (order/duplicates ignored, no normalization); mismatch rejects. String outputs supply string consumers and are JSON data; general JSON outputs do not guarantee string consumers; `http-response` feeds checks only. References are inspected only in supported slots; a producer must exist, be in the catalog, type-match the consumer slot and rank earlier by connection order. Typed draft nodes may omit whole parameter objects; present parameters must be fully valid; invalid partial payloads are rejected, not retained. `ready` graphs require every parameter, the reviewed linear topology, compatibility and a top-level global `load`; `load` is optional in draft.
- Runtime ambiguity (header case/repetition, cookies, transport/invalid JSON), CSV dialect/encoding/malformed-row handling, graceful-stop and graph-wide producer/type compatibility remain deferred.
- Runs REST: run start accepts an already compiled script (opaque string, Phase 5 output), never a graph. POST /runs → 202 + runId (async); Idempotency-Key header dedupes identical key+payload to 200 with the existing runId; POST /runs/{id}/stop → 202; unknown runId → 404 on stop/summary; premature summary → 409. Exact statuses pending|running|finished|failed|stopped: `finished` means the engine completed including threshold evaluation (summary carries `thresholdsPassed`), `failed` is reserved for engine/infra errors. REST `vus`/`durationMs` always override script-embedded options; `cpuMillis`/`memoryMiB` are explicit required positive safe integers; attachments are opaque ids only, no byte upload. Static Bearer token on all /api/* except public unversioned `/healthz` (preserved, process-only); API bodies carry explicit `version: 1`. Final summary is cumulative, separate from the 05 WS window topic. These are schemas/OpenAPI declarations, not handlers, idempotency stores, schedulers or engine adapters.
- Metrics WS (05): topic `/ws/runs/{runId}`; frame `{version:1, type:"metrics", runId, seq, window:{startMs,durationMs:1000}, reqPerSec, latencyMs:{avg,p90,p95,p99}, httpFailureFraction, activeVUs, failedChecks}`. Fixed 1s window, monotonic seq per run; units ms / fraction [0,1] / ≥0 rates / nonneg safe-integer counts (consistent with 03e+04); no-sample windows carry explicit `null`, never a silent 0. Window topic is separate from the 04 cumulative final summary. Routing: browser same-origin via Next proxy rewrite; orchestrator port not exposed. Scope: metrics frame only — terminal/error/reconnect-replay frames deferred to a distinct capability. These are schema/doc declarations, not handlers, sockets, aggregation or broadcast.
- Generated install surfaces: `node_modules/**`, `apps/web/node_modules/**`, `packages/shared/node_modules/**`. Explicit verification writes/downloads: `node_modules/.go-cache/**`, `node_modules/.go-mod-cache/**`; human subsequently approved generated `node_modules/.vite/**` writes to retain `pnpm test`.
