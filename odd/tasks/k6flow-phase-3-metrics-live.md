- New dependency authorized: **`github.com/gorilla/websocket`** (human choice; verify go floor ≤1.25 before pinning, keep directive `go 1.25.0`).
- Four approved Phase 3 policies (human, 2026-10-02):
  1. **WS library**: `gorilla/websocket` for the orchestrator endpoint.
  2. **WS auth**: token via `Sec-WebSocket-Protocol` subprotocol (browser cannot set Authorization on handshake; no token in URLs/logs); invalid/missing → handshake rejected 401-equivalent. Consistent with init:111 service auth.
  3. **Backpressure**: bounded per-subscriber buffer (64 frames), **drop-oldest** on overflow (client sees latest; `seq` stays monotonic with allowed gaps — schema enforces range only, ordering is a producer obligation per contract); reconnect gets no replay (fresh frames from the next window; replay/terminal frames remain the deferred capability).
  4. **Dashboard scope**: minimal `/runs/[runId]` page — runId + WS token input (no login; Phase 4 owns auth), current window + last-N windows table (req/s, latencies, failure fraction, active VUs, failed checks), zero new TS dependencies.
- Frame semantics (FIXED by Phase 1, implemented not reinterpreted): fixed 1000 ms windows anchored at run start (`window.startMs` run-relative ms); values are PER-WINDOW (a metrics frame never carries cumulative totals or `thresholdsPassed`); `reqPerSec` = window requests / 1 s; `httpFailureFraction` = window failures / window requests; `failedChecks` = window delta; `activeVUs` = gauge for the window; sample-derived trio (`reqPerSec`, 4 latencies, failure fraction) null EXACTLY together on no-request windows — never silent 0; `activeVUs`/`failedChecks` never null; `seq` monotonic per run.
- Streaming architecture (parent-decided): engine's `Output()` stream is consumed ONCE by a tap goroutine per run — one path feeds the window aggregator (broadcast), another preserves the existing final-summary accumulation (k6sum semantics unchanged; all existing engine/k6sum tests must stay green). Windows anchored at run start: `[n·1000, (n+1)·1000)` run-relative.
- Connection lifecycle (parent-decided, contract-conformant): subscribers may connect any time; frames emitted only when a run-window closes (all subscribers of that run get complete windows); when the run reaches a terminal state the server closes connections (code 1000) with NO terminal frame (deferred capability); unknown runId → handshake rejected (404-equivalent); one subscription per connection (runId from path).
- Next proxy: `apps/web/next.config.ts` rewrite `/api/ws/runs/:id` → `ws://<orchestrator>:8080/ws/runs/:id` (orchestrator port not exposed; browser never connects directly — contract §routing).
- Keep ~400 authored lines for TS/declaration units; Go runtime units plan ≈1,500 (Phase 2 human-set expectation); overages need human disposition (accept/trim/split). gofmt-canonical, budget-gate projections BEFORE authoring.
- Advisory backlog stays unauthorized (19+ items from Phases 1–2); `.env.example`, `deploy/docker-compose*.yml` edits, Dockerfile changes need explicit human authorization.
