## Runtime protocol and limits
Counter `k6flow_diagnostic_event`: value elapsedMs 0–30000; exact tags seq/nodeId/event/httpStatus/outcome/reason. At most 100 unique node IDs, 128 UTF-8 bytes each, 201 contiguous ordered events; HTTP status 0–599. Events enter/exit/skipped/complete; outcomes pending/success/failure/skipped; fixed reasons none/disabled/prior-failure/http/extraction/check/pool/exception. Completion ID empty; timing/status only on exit. Real k6 zero-value points and hostile-scenario one-VU/iteration-zero enforcement verified; system tags disabled.

Snapshot: `{version:1, runId, status, diagnostic:{nodeIds}, trace:{state,events}}`. Trace states pending/running/complete/failed/incomplete/interrupted. A finished run can have failed trace. Missing completion/init failure is incomplete; explicit Stop/watchdog interruption wins. Server wrapper ignores submitted options/scenarios, forwards setup/default/teardown; 35s watchdog. Owned proxy: 5s timeout, 128KiB response bound, no-store, sanitized errors.

Forever-blocked frame/finisher callbacks can retain delivery goroutines and delay finish notification; authoritative terminal state, cleanup and capacity do not wait for those callbacks. Other synchronous RunEventSink callbacks remain outside that guarantee. Remove failures are observable, not impossible. Existing save cancellation is logical; server writes may finish.
